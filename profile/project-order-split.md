# 项目四：订单拆单系统标准化重构

## 项目背景

针对拆单规则分散、扩展性差、用户体验割裂及业务影响不可控的问题，主导拆单系统标准化重构，构建规则抽象、灰度发布与数据推演一体化体系，实现拆单能力平台化升级。

## 技术栈

- Spring Cloud
- Spring Boot
- MyBatis
- MySQL
- Redis
- Elasticsearch
- Kafka
- Apollo
- XXL-JOB
- Maven

## 个人职责与成果

### 1. 重构拆单规则

将多场景定制逻辑抽象为“四维度模型”：

- 指定类目
- 多发货方
- 多履约地
- 独立服务与虚拟商品

统一执行链路并收敛不必要拆单场景，实现用户侧“无感拆单”，整体拆单率下降 6.04%。

### 2. 收敛拆单时机

将拆单时机统一至订单提交履约阶段，降低链路复杂度与状态不一致风险，提升系统稳定性与一致性。

### 3. 构建历史数据推演体系

基于历史数据回溯，在影子环境复现真实业务链路，对比新旧规则执行结果并量化核心指标影响。

实现规则变更影响可评估与可验证，降低重构风险。

### 4. 建设双阶段灰度发布机制

设计拆单模式（1:1 / 1:N）与规则版本双维度灰度，结合 Apollo 实现秒级配置下发与动态流量控制。

保障系统平滑切换，可用性达到 99.95%+。

### 5. 拆单引擎解耦与策略化改造

基于策略模式 + 工厂模式实现规则可插拔与配置化管理。

新业务接入周期从 3 天缩短至 1 天，开发效率提升 60%+。

### 6. 一致性与并发控制体系

设计“三级幂等机制 + 双阶段分布式锁（拆单锁 / 取消锁）”，保障核心链路幂等性与并发安全。

重复拆单率降至 0。

## 可量化结果

- 整体拆单率下降 6.04%。
- 系统可用性达到 99.95%+。
- 新业务接入周期从 3 天缩短至 1 天。
- 开发效率提升 60%+。
- 重复拆单率降至 0。

## STAR 摘要

- Situation：拆单规则分散、扩展性差、体验割裂，规则变更的业务影响难以提前评估。
- Task：主导拆单系统标准化重构，提升规则抽象能力、稳定性、可灰度能力和平台化复用能力。
- Action：抽象“四维度模型”，统一拆单时机，建设历史数据推演、双阶段灰度、策略化规则引擎、三级幂等和分布式锁机制。
- Result：整体拆单率下降 6.04%，系统可用性达到 99.95%+，新业务接入周期从 3 天缩短至 1 天，重复拆单率降至 0。
